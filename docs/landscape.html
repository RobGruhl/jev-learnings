Landscape, October 2026

Decision models went from one vendor to a crowded field in about a month. Here's what changed since our benchmark runs in early October: the Claude lineup, OpenAI's Decisions API, and the open-weight models that, by their own published numbers, may no longer be mid.

Provenance. Our own measurements are on Four ways compared, Open weights caught up and Nimble takes the lead. Everything on this page comes from vendor documentation, release notes, public leaderboards and press as of October 12, 2026, and we haven't reproduced it. Vendor benchmark claims are marked as claims. The field changes daily.

The Claude lineup

Three new Claude models shipped in the last four weeks. All have a 1M-token context window and up to 128K output tokens.

  • Anthropic has no decision or classification endpoint and no log-probabilities. The closest mechanism is structured outputs plus strict tool use, which is what our Haiku adapter used.
  • Haiku 5.5 is a remarkable price drop: the previous Haiku 4.5 was $1 / $5, ten times more.
  • Sources: Claude pricing, models overview, release notes.

Jev: unchanged

  • jev-1.13.0 is still the only model; jev-latest and jev-preview both point to it. No 1.14 yet.
  • Still $0.042 per million input tokens, output free; still text-only; 64k context per request.
  • Rate limits are "adjusting dynamically" under demand, per TypeSafe.
  • The Python SDK reached v0.7.3 (October 9) with concurrency and TLS fixes. Jev is also listed on OpenRouter as typesafe/jev-1.13.
  • Source: docs.typesafe.ai/models.

Bespoke Labs: Nimble, a second hosted decision model

  • Hosted at api.bespokelabs.ai/v1/systemone, in Jev's own request and response shape, so the TypeSafe SDK and our harnesses ran against it unchanged. $0.04 per million input tokens, output free; failed requests aren't charged.
  • One model is served: nimble-v4-max (27B, per the launch announcement). nimble-v4 is deprecated and, like nimble-latest, points to it; nimble-v3 is deprecated. An older docs table still lists nimble-v4 as a separate fast, cheap model; on October 27 it returned max's answers, token counts and latency. Ask for nimble-v4-max by name; there is no revision selector.
  • Limits: 1 to 64 questions per request, 256k prompt tokens per question (never truncated: an over-long request is an error), a 1 MiB body, and 4 concurrent requests until an organization first buys credit, then 100.
  • Open weights too, but not v4's. Bespoke publishes Bespoke-Nimble-9B (a LoRA adapter over Qwen3.5-9B, Sept 18) and its v2 and v3, Bespoke-Nimble-27B-v3 (Oct 9) and Nimble-v4-max (Oct 18) on Hugging Face. There is no v4 9B checkpoint. The official MLX scorer refuses quantized weights, so the 9B wants about 19 GB at BF16 plus a merged copy on disk. ggml-org's Q8 GGUF of the v3 repo does run on a 24 GB Mac through Ollama, at ~13 GB.
  • We measured the 9B on a rented H100. It matched Jev on 38 wine questions, trailed Jev as a single judge, and trailed v4-max everywhere. Its current release judged wine worse than its launch checkpoint (results).
  • Our result: v4-max led every harness we ran except the mail sorter. See Nimble takes the lead.
  • Sources: Nimble overview, pricing, limits and errors, huggingface.co/bespokelabs.

OpenAI: Decisions API, Luna and Terra

  • Decisions API has been in public beta since October 6, with GA promised "in the coming weeks." Still only gpt-6-luna and no pinned snapshot. Still $0.10 per million input tokens, with no charge for output or caching. It accepts images as inline base64. Rate limits aren't documented.
  • Luna is also a general model. gpt-6-luna (Sept 22) is OpenAI's cheapest general text model: $0.10 in, $0.50 out per million, 1.05M context, on Chat Completions, Responses and Batch. Its predecessor gpt-5.6-luna is still listed at $0.20 / $1.20.
  • The general lineup, as of October 27: GPT-6 Astra ($10 / $50), GPT-6.1 Sol ($2 / $10), GPT-6.1 Terra ($1 / $5, knowledge cutoff June 1, 2026) and GPT-6 Luna ($0.10 / $0.50, cutoff May 18). All have a 1.05M context and 128K output. Luna and Terra take strict structured outputs at effort low; they return token log-probabilities only at effort none.
  • Asked like Haiku, Luna is a different judge. Through the Responses API with a structured-output schema it tied Nimble on wine and Jev on the mail sorter, at Haiku's cost and with Haiku's re-ask wobble. Terra is steadier and costs 10× more per token. See Nimble takes the lead.
  • OpenAI has not adopted the /v1/systemone request shape that others are converging on; you still need an adapter.
  • Sources: Decisions guide, gpt-6-luna, changelog.

What it takes to run them

The models that beat Jev on JevBench are big. Before you plan on "free," check what the hardware costs. A model's weights take roughly parameters × bytes per parameter: 2 bytes at BF16, 1 at 8-bit, 0.5 at 4-bit. Then add a few GB for the KV cache and the runtime. These are rule-of-thumb estimates, not measurements:

Model class4-bit8-bitBF16Realistic hardware
2B–4B (Decider 2B, APUS 4B, H2O-Lightning-4B, Gemma 4 E2B/E4B)1–2 GB2–4 GB4–9 GBAny recent laptop
9B–12B (APUS 9B, Decider 12B)5–7 GB9–13 GB18–24 GBA 16–24 GB laptop if quantized; BF16 wants a 24–32 GB GPU
26B-A4B mixture-of-experts (Decider 26B)~14 GB~27 GB~52 GBAll 26B must sit in memory even though only ~4B work per token, so it's fast once it fits. A 24 GB GPU at 4-bit; a 48 GB+ machine at 8-bit; an 80 GB GPU at BF16 (Strands' latency figures are from an H100)
31B dense (the top of the Capability board)~17 GB~33 GB~62 GBEvery parameter works on every token, so it's several times slower per request than a 4B. A 24 GB GPU or a 32 GB+ Mac squeezes 4-bit; a 48 GB card (L40S, A6000) or a 64 GB Mac for 8-bit; an 80 GB H100 for BF16
35B-A3B mixture-of-experts (APUS 35B)~19 GB~37 GB~70 GBLike the 26B, but larger: a 32 GB+ machine at 4-bit
  • On a 24 GB Apple-silicon laptop (our test machine): the 2B–4B models run comfortably, and 9B–12B fit if a quantized build exists. The 26B-A4B at 4-bit is borderline, because macOS lets the GPU use only part of unified memory by default (roughly two-thirds to three-quarters). 31B dense and 35B-A3B don't realistically fit. Downloads are large too: budget the model's size in free disk, twice over while converting.
  • Check the runtime, not just the size. Some decider servers run on PyTorch, which on a Mac means BF16 on the GPU unless someone publishes a quantized MLX or GGUF build. A 12B in BF16 (~24 GB) won't fit a 24 GB Mac.
  • Quantizing changes the answers. 4-bit weights shift probabilities. Treat a quantized model as a new model: re-grade your questions and re-fit thresholds (they belong to a model, runtime and rubric triple).
  • Rented GPUs have a price too. We paid $3.29 an hour for an 80 GB H100. At our measured hosted price, Jev answers about 52,000 typical requests for that, and a busy H100 running Kev-27B or GEV-26B answered 9,000–12,000, so about 4–6× Jev per request (see the cost ladder). Bespoke-Nimble-9B is smaller, but its scorer reads the prompt once per question, so the same H100 answered only about 2,800 six-question requests an hour: about 18× Jev. Open weights win on privacy and at high, steady volume, not automatically on cost.

How to read this

JevBench is a public benchmark, and public sets leak into training. Our own lesson was that benchmark wins didn't predict mail wins: the 2B decider tied Jev on several JevBench families and still trailed it badly as a sorter feature source. A 31B model is also not a laptop model: see what it takes to run them. The honest next step was to run these models through the same wine, mail and page harnesses. The Decision Skeleton makes that a one-module job: swap the backend, re-run the eval.

Done October 14 for six 26–27B models: most now match Jev on our private tasks. See Open weights caught up.

Other entrants and the emerging standard

  • Microsoft Decision-1 (Foundry, Oct 9): hosted only, text only, 32K context, priced like Jev at $0.042 per million input tokens. Microsoft claims best accuracy on 36 benchmarks.
  • /v1/systemone is becoming a de facto API. Reports say AWS, Upstage and Ollama have aligned on TypeSafe's request shape. Ollama v0.35+ and llama.cpp's server can serve it locally, and Pydantic AI has a SystemOneModel. Bespoke Labs' hosted Nimble speaks it natively. A decision model you can swap without an adapter is now realistic for everyone except OpenAI.
  • Other hosted decision APIs are appearing (Upstage Solar Decide, Perplexity, and others) from single-source announcements; treat them as unverified.
  • Google, Meta, Mistral and Nvidia have no first-party decision model yet; Gemma 4 and Qwen 3.5/3.8 are the common bases for others' fine-tunes.

What this changes in our advice

  1. Write against the /v1/systemone shape and keep backends swappable. The cost of switching is now an eval run, not a rewrite.
  2. Re-test open weights before calling them mid. If a 12B–26B open model matches Jev on your data, privacy and zero marginal cost become free wins. On ours, the 26–27B models did (results).
  3. Haiku 5.5 changed the "small LLM" math. At $0.10 / $0.50, the price gap to decision models is now 5–7×, not 50×. Repeatability, latency and calibration, not price, are the reasons to prefer a decision model.
  4. Pin what you can. More vendors means more silent model updates. Thresholds belong to a (model, runtime, rubric) triple.
  5. Jev has hosted competition at its own price. Nimble v4-max took Jev's request shape unchanged and beat it on wine and mail concepts (results). Evaluate both on your data, refit thresholds, and check repeatability before you freeze one.
  6. Test the call path, not just the model. The same gpt-6-luna went from Jev's level to the top of the wine table when we asked it as a chat model instead of through the Decisions API.
