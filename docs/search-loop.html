Case study Part 3 of 4 · the loop, built

The loop, built

An open question is hard to judge paragraphs against, because you don't yet know what the answer looks like. A draft answer fixes that. Handing Jev the question and a first draft, then asking how each paragraph relates to that draft, gave the strongest gain we measured in the pipeline. So the best recipe isn't a funnel from code to Jev to LLM. The LLM sits in the middle and sends Jev back once.

The recipe

  1. JevCodeRead everything

    Jev scores every paragraph with the rely statement. Code adds a grep sweep for the names in the question.

  2. JevGrow passages

    For each top paragraph, Jev decides how far the passage runs, up to three rounds each way.

  3. LLMWrite a draft

    Sonnet answers from those passages.

  4. JevCodeReread with the draft

    Jev rereads the top 2,000 with the draft in its state. Code blends the two rankings and drops what was already read.

  5. LLMWrite the answer

    The top 20 to 40 new paragraphs are grown and added, and Sonnet writes the final answer. Then stop.

rely   = jev(every paragraph, RELY, question)        # $0.233 for 28,167 paragraphsnames  = grep(names in the question)                 # free, catches exact mentionsfirst  = grow(top(rely) + names)                     # Jev decides each passage boundarydraft  = write(question, first)second = jev(top 2,000 of rely, SECOND, question + draft)   # about $0.02blend  = sum over both rankings of 1 / (60 + rank)   # reciprocal rank fusionnew    = top 20 to 40 of blend, minus firstmore   = grow(new)answer = write(question, first + more)# no third pass: it adds nothing

The answer test started from the keyword-gated first pass in part 1, then added paragraphs from the full-read blend. This full-read-first version has run on one real question and was not scored against gold. Reading everything first should help, based on part 2, but that's an inference.

The two statements, verbatim

The first pass asks about the question. The second asks about the draft:

This paragraph states something an answer to the question in `question` would rely on.

Compared with the answer in `answer`, this paragraph adds something missing, contradicts or corrects it, or expands on it, in a way that matters for the question in `question`.

Strip citations from the draft before it goes in the state. The combined statement matters: single statements about adding, correcting or expanding did little, and "corrects" alone lost ground on held-out questions. Blending matters too: the combined statement alone found 21 missed facts where the blend found 28.

  • The second pass helps. +8.8 points [4.5, 12.9] against the first, 13 questions better and 1 worse, p .002. It held on tuning (+8.4) and held-out (+9.5) questions.
  • Its edge over reading further is unsettled. +5.3 [−0.2, 11.1], and +1.4 on tuning against +13.1 held out.
  • A third pass doesn't. −0.8 [−4.7, 3.2]. Suggested terms reached new paragraphs, but +1.3 [−3.3, 6.0] is within noise.
  • The draft seems to matter. Earlier second waves with no draft barely helped: aiming at gaps added 1.7 points of evidence, and letting an LLM aim it added 1 more for 1.6M extra tokens. Those used a different stack and an evidence-only measure, and this +8.8 also includes the gain from reaching the full read, so we can't separate the two.
  • It has a cost. A second writer call roughly doubles latency unless the first draft is quick. The recipe hasn't been timed end to end.

These totals can't be compared with the 27 of 51 in part 1. Writers here ran to about 670 words against a 500-word limit, and the scorer changed. Comparisons between arms in one table hold.

Passages: let Jev find the edges

A hot paragraph doesn't automatically pull in its neighbours. Jev decides each boundary. Across the first-pass runs, 960 hot paragraphs became 858 passages of 2.95 paragraphs on average, and 32% stayed single. Turning growth off lost 13.4 points of evidence.

Fixed neighbours are the tempting alternative, and they aren't the main problem. Always adding one paragraph each side would add about 67 paragraphs and 33k characters to each answer. Here's where the 36 facts missing from first-pass evidence were (112 of the 148 were already in):

Knowing when to stop

The natural router is a question to Jev: is this evidence enough? On the textbook corpus it barely noticed when a whole intended source was removed: pooled AUC about 0.55, with a median drop of 0.013 against a between-question spread of 0.123. Scores for each part of the question can point at a gap once one exists, but only with a full copy to compare against, which production doesn't have. So we don't route on sufficiency. One second pass, then stop, was the rule that held up. In part 4, Opus stopped when results stopped being new, which is a different test that works for an LLM reading the results.

The sources are now the constraint

Why do useful paragraphs rank low? Opus read about 180 of them and gave a rough count:

ReasonShare
Table rows or footnotes with their headers cut off35%
Answers a late part of a many-part question20%
Spoken or garbled transcript17%
Refers to the subject only indirectly10%

Most of that concerns what Jev is shown, not how it's asked, which is why wording did so little. An audit of paragraph structure agrees:

SourceSplit mid-sentenceOther unfinished endingsRead

The same rule holds as in the cascade: a decision model judges what's in front of it. It can't recover a column header that isn't in the state. Rebuilding tables and transcripts is the next step, and it changes every paragraph id, so baselines must be rerun.
