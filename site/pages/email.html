An inbox, the testbed

The other half of this site's evidence comes from one personal inbox. The goal was to never miss mail that needs action, especially mail with a deadline, without the owner having to read an inbox at all. A decision model asks bounded questions of every message, code adds the facts it can't know, a learned sorter decides how much attention each message gets, and Claude reads what's left. This four-part case study shows how that was built and measured, and what it taught. It reports counts and rates only. No mail, senders or people appear here.

The goal

The owner's brief was short: less email, file what doesn't need action for reference, and never miss the important. The model for success was a good human assistant. They read everything, bring you the few things that need you with what to do next, and keep the rest filed where you can find it. The owner stays in the loop, and nothing is automated until they say a judgment is settled.

That makes the cost of errors lopsided. Showing the owner an extra newsletter costs a few seconds. Filing a failed payment or a deadline unread can cost real money and is noticed late. Every number in this case study is set by that asymmetry: misses are counted exactly, and the filter rate is what you get at the number of misses you'll tolerate.

Two things stood out early. First, a third of the labels were low-confidence, and the labelers split on the same recurring patterns: sign-in alerts, failing builds on the owner's own code, appointment reminders and utility bills where autopay was unclear. Those aren't model questions; they're the owner's to rule on. Their rulings moved the action count from 293 to 244, about a quarter of the action load (part 4). Second, noise is concentrated: 50 senders sent only noise over the three months, 19% of all mail.

Four rules that kept it honest

Code

Mail is private, gated in code

Mail, labels and run logs live only in a private folder that version control ignores. Any backend that isn't on the local machine refuses private mail unless an explicit flag is set, and the hosted model saw this mail only after the owner approved it. Write-ups report counts and rates.

Code

Read-only, and no retyping

Nothing in the lab changes a mailbox. Unsubscribes and filters go through a separate tool, behind the owner's approval. Agents never transcribe mail: the harvest is byte-exact, and links are taken from the raw message by code, so a reader names the link text and code resolves the URL.

Jev Code

Rules are facts, not overrides

Only bad input and embedded instructions force a message to review. Every other rule can only keep mail out of the zero-token buckets. The model's category never suppresses a message on its own. An early "doesn't look bulk" protection was demoted after three labeled sets showed it saved nothing and cost filtering.

Human LLM

Honest evaluation

The question set and thresholds were frozen and committed before each held-out month ran. Every filed message was labeled, so misses are exact; a seeded sample of escalated mail gave precision. Labels were made blind. Anything tuned on a month counts as in-sample, and the owner's rulings override provisional labels.

Two models were measured on this mail: the hosted Jev (jev-1.13.0) and a local 4B open-weight model behind a Jev-compatible gateway. The local model mattered early, because it let real mail stay on the laptop. It runs hot, though, and it hit a quality floor (part 3).
