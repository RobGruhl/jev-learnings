A field guide · October 2026

Match the tool to the work.

A decision model reads text and returns typed answers with probabilities: which of these options, how likely is this true, where on this scale. It is fast and costs fractions of a cent per decision. It sits between your code and a big language model, and it handles the judgment calls that don't need an essay. This site teaches that idea from a five-year-old's version up to the engineering, using what we measured in two real projects.

The ten-line version

  1. Put each kind of decision in the cheapest tier that can make it correctly: code first, a decision model for judgment, the LLM for novelty, the human for preference.
  2. When the decision model is wrong in a consistent direction, or the question has a computable answer, move it to code.
  3. The decision model judges the decision against the state it is shown. It can't see a consequence the state doesn't contain, so code must put that consequence in the state.
  4. Doubt is good evidence when it is high. Bugs often sit just below the escalation line, though, and the worst ones never reach the model at all: they are planner gaps where every option offered was bad.
  5. A playbook line turns a novelty escalation into a confident decision next time. One sentence of context moved doubt from 0.71 to 0.35.
  6. Verifiers must check outcomes (the count went up), not starts. They must also accept deliberate stops as success.
  7. In an agent loop, LLM wakes are the scarce resource. Batch sizes, restock sizes and how often "nothing to do" happens decide the wake rate.
  8. Prefer one contrastive Choice whose options name the near misses. Grade every question against its own concept.
  9. Use answers as features in a learned combiner, not as hard thresholds. Validate on a new time window, not just cross-validation.
  10. Safety belongs in the fastest tier, and the environment (tabs, focus, disconnects) is its own failure class.

Where the evidence comes from

An email first pass

A personal inbox, studied across several held-out months. Every message got a set of decision-model questions plus deterministic rules, and was sorted into buckets that set how much LLM attention it gets. Junk cost zero LLM tokens. Concept labels were made blind.

A long-running operations agent

An agent that ran for days in a web browser: it scheduled production jobs, bought and restocked supplies, managed limited storage, and kept a health metric above a floor. Code planned and verified, the decision model judged priorities on every tick, and Claude woke on escalations. Several hundred logged ticks and about 65 resolved escalations. The decision model cost under $0.10 a night.

The testbed was an idle game (Melvor Idle) chosen because it runs unattended for days. The general pages describe it in plain operations terms: jobs, supplies, stock, storage. The Melvor case study shows the real thing.

The decision model in both was Jev, TypeSafe's hosted model (jev-1.13.0). In October we ran the same harnesses against OpenAI's Decisions API, two open-weight decision models and Claude Haiku 5.5. The results are on Four ways compared.
